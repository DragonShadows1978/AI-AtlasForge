ERROR CONTEXT CAPTURED PER ERROR
================================================================================

Each CUDA error exception includes:
- Source filename
- Function name
- Exact line number
- CUDA error code (enum value)
- Error string (from cudaGetErrorString)
- Context-specific help text
- Async error information (if applicable)
- Device-side assertion details (if DSA enabled)
- Kernel launch information
- Thread/block coordinates (from device-side code)

================================================================================
BUILD CONFIGURATION FLAGS
================================================================================

COMPILE-TIME CONTROL:

-DSTRIP_ERROR_MESSAGES
  Purpose: Remove detailed error messages for binary size reduction
  Default: Messages included

-DTORCH_USE_CUDA_DSA
  Purpose: Enable device-side assertions at compile time
  Default: Disabled (adds ~64KB overhead)

-DFBCODE_CAFFE2
  Purpose: Set maximum GPU count to 16 (Meta/Caffe2 internal)
  Default: 120 GPUs (public PyTorch)

================================================================================
RUNTIME CONFIGURATION
================================================================================

Environment Variables:
  TORCH_USE_CUDA_DSA=1            Enable device-side assertions at runtime
  TORCH_CUDA_DSA_STACKTRACE=1     Capture kernel launch stack traces

API Control:
  CUDAKernelLaunchRegistry::get_singleton_ref().enabled_at_runtime = true/false
  CUDAKernelLaunchRegistry::get_singleton_ref().gather_launch_stacktrace = true
  c10::cuda::warning_state().set_sync_debug_mode(SyncDebugMode::L_WARN)

KEY FINDINGS
================================================================================

1. ERROR DETECTION
   - Macro-based with immediate context capture
   - No automatic retry (caller responsibility)
   - Fast-path optimization for success case

2. ERROR PROPAGATION
   - Exception-based (c10::AcceleratorError)
   - Rich context in every exception

3. RESOURCE CLEANUP
   - RAII guards guarantee restoration
   - Device/stream contexts always restored
   - No leaks on exception

4. DEVICE DEBUGGING
   - Managed memory + circular buffer
   - Post-mortem kernel launch inspection
   - Thread/block coordinates captured

5. LIBRARY COVERAGE
   - 7 CUDA libraries directly supported
   - Specialized error messages per library
   - Custom handling (e.g., NaN detection)
