PART 3: Technical Details on Launch Parameter Constraints

GPU Constraints:
- NVIDIA constraints for blockDim (1024 max total)
- Grid dimension constraints
- Occupancy constraints (threads/SM, blocks/SM)
- Register constraints per thread

Memory Layout in CUDA:
- Global Memory (GB scale, 100 GB/s)
- Shared Memory (KB scale, ~2 TB/s with good banking)
- Registers (per thread, extremely fast)
- L1/L2 Cache (automatic, variable speed)

Bank Conflict Patterns:
- Pattern 1: GOOD - Sequential access, no conflicts
- Pattern 2: BAD - Bank conflicts causing 8x slowdown
- Pattern 3: SOLUTION - Padding to break conflict pattern

KEY RESEARCH FINDINGS SUMMARY
================================================================================

1. CUDA CODE GENERATION
   Location: src/target/codegen_cuda.cc
   Process: TIR → CUDA C++ via thread binding and synchronization
   Output: Kernel with __global__ signature, blockIdx/threadIdx calculations

2. LAUNCH PARAMETER SELECTION
   BlockDim: 32-1024 threads (powers of 2), constrained by GPU limits
   GridDim: Calculated as ceil(problem_size / blockDim) at runtime
   Bind operations: Determine which axis maps to which thread/block dimension

3. AUTO-TUNING PROCESS
   Algorithm: Evolutionary search with mutation-based exploration
   Cost Prediction: XGBoost model with 18% MAPE accuracy
   Search Speed: 1000 trials explores ~0.01% of space efficiently
   Convergence: 3x faster than random search

4. PERFORMANCE IMPACT
   Typical: 2-4x speedup over naive defaults
   Extreme cases: Up to 10x improvement
   End-to-end: 8-15% latency reduction on full models
   ROI: 4-8 hours tuning × millions of inferences = large payoff

5. KEY MECHANISMS
   Transform Primitives: Split, Bind, Reorder, Fuse, Parallel, Unroll, Vectorize
   Search Strategy: Evolutionary with tournament selection
   Feature Engineering: 50+ features capturing loop structure and memory patterns
   Validity Checking: Ensures schedules respect GPU hardware constraints
